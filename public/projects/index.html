02 — How we build

The same discipline, every time.

Problem

Named from a real situation — a lab that needs data, a network that goes down, a language model that ignores Bangla.

Approach

Smallest thing that works, built to be read. Design decisions documented in the repo, not just in someone's head.

Result

Shipped, measured, and written up. A project that isn't documented is a demo, not a deliverable.

→ every repo ships with a README that explains the architecture, not just the buttons.
