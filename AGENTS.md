## Architecture
- `scripts/build.js` — template engine + site builder. Key functions: `tokenize`, `renderTokens`, `evalCond`/`condVal`, `splitArgs` (paren-aware arg splitting; quotes inside parens preserved), `evalVal`, `resolve`, `compare`, `truthy`, one-arg helpers (`fmtYear`, etc.), `navFor(page)` computes `isActive`. Guards: depth >60 or iterations >1M throw.
- Template syntax: `{{ .path }}`, `{{ each .arr }}...{{ end }}`, `{{ if eq/ne/lt/gt/le/ge ... }}`, `{{ if not ... }}`, `{{ if or (eq .a "x") (eq .b "y") }}` / `and`, `{{ else }}`, `{{ include "partials/x.html" }}`, `{{ helper path }}`.
- Engine history (fixed bugs — do not regress):
  - `or`/`and` args must be evaluated as conditions — `condVal()` strips wrapping parens and routes condition-looking args to `evalCond`, bare paths to truthy values.
  - `splitArgs` must group `(...)` segments (paren-depth tracking) and preserve quotes inside paren groups; otherwise `(eq .role "X")` splits into `(eq`, `.role`, `X)` and the stray `(eq` string makes `or` always true.
- Layout: `main[data-horizontal]` = flex row (`overflow-x: auto; overflow-y: hidden`) on ≥900px; vertical below. **Every direct flex child needs `flex: 0 0 auto`** or it gets flex-shrunk: `.site-nav` and `.sec-footer` both had this bug (nav squashed to ~35px; footer crushed 1382→522px with overlapping text). `.sec` already has it.
- Breakpoint: 900px (hx-body class toggled by JS). `main.hx` display:block + `body:not(.hx-body)` rules handle vertical mode. NOTE: `hx-body` class may persist below 900 (CSS switches layout); scope hx-only rules with `body.hx-body` AND `@media (min-width: 900px)` to be safe.
- **STICKY VS ROOT OVERFLOW (fix 2026-09-18 — do not regress)**: the reset (02-reset.css) sets `html { overflow-x: hidden }` because fixed decorative layers (bg-grid/glow, off-canvas mobile-menu) bleed past the viewport. It used to ALSO set `overflow-x: hidden` on `body` — that quietly killed `position: sticky` on `.site-nav` for the VERTICAL pages (article + event singles): an overflow:hidden/auto/scroll ancestor becomes a scroll container, so the nav stuck to BODY (which scrolls away with the document) instead of the viewport. Symptom: scroll down an event/article page and the nav vanishes while the fixed 2px `.progress` line keeps floating at top-56 on its own ("progress indicator renders wrong"). `body` now uses `overflow-x: clip` (comment in 02-reset.css explains). `clip` clips bleed the same way but does NOT create a scroll container, so sticky works again. `html` KEEPS `hidden` on purpose — html IS the document scrollport; `clip` on html would not propagate and could disable viewport scrolling. Rule of thumb: a non-root ancestor that must clip horizontally uses `clip`, never `hidden`/`auto`/`scroll`, if a `position: sticky` descendant lives inside it.
- Sections: `.sec { min-height: 100%; flex: 0 0 auto }` — they GROW beyond viewport height if content demands, but `main.hx` clips vertically (`overflow-y: hidden`), so tall content is cut on short viewports. Keep sections ≤ ~viewport height at 650px tall viewports.
- Nav: `position: sticky; top: 0` + `flex: 0 0 auto`; content starts below it. Mobile menu is CSS-visibility toggled (NO `hidden` attribute — was removed).
- Theme: dark-first (`--bg #0c0f13` etc.), light theme in vars; accent `#4fd1a5`/`#157a5b`; inline head script sets `data-theme` pre-paint; persisted `localStorage('dcitc-theme')`; `prefers-reduced-motion` disables animations.
- Scroll: pure smooth manual horizontal scroll (easing 0.16) — snap was deliberately removed. `.hx-status` bottom-left readout was deliberately removed (markup/CSS/JS all gone).
- Reveal animations: `reveal.js` has a rAF safety net revealing in-view/already-past elements.
- Parallax `[data-plx]`, float animations, anime.js vendored at `static/js/vendor/`.
- Content: `src/data/*.json` (site, nav, team, projects, resources, achievements), `content/blog/*.md` (Tech Journal) + `content/events/*.md` (events calendar) + `content/gallery/*` (photo strip — pure image files) — content/<type> authored in its own format, `src/pages/*.html`, `src/partials/{head,header,footer,scripts}.html`. Directory-style output: `public/<page>/index.html`, items at `public/<type>/<slug>/index.html`. Article pages (`article.html`) intentionally have no footer.
- **Markdown blog + events** (replaced mock `src/data/posts.json` AND `src/data/events.json`, both deleted): one `.md` per item under `content/blog/` / `content/events/`; filename IS the slug. Pipeline lives in `scripts/lib/content-source.js` (loadPosts/loadEvents): `escHtml()` + `marked.use()` (gfm; code-fence renderer override emits `<pre class="code"><code>`) + frontmatter `js-yaml` + `sanitize-html` (allowlist; `pre` keeps only class `code`; external links get target/rel) — keep the marked.use()/renderer block ABOVE both loaders or events render without the pre.code override.   Blog: title+date required. Events: title+date+status required (status ∈ upcoming|ongoing|past, validated — drives chips/badges + home list; PLACEMENT on the events index is config-driven, see `resolveEventsPage`); program[{time,title}], speaker{name,role}, resources[], register, location/duration/level stay STRUCTURED frontmatter because the deck/timeline render them as components; optional markdown body → event page About plate (`{{ .item.contentHtml }}` in `.md-body.ev-brief`, falls back to short `description`). Both: draft:true dropped before anything runs, sorted date-desc (tie slug asc) for codes/‌pager, codes ART.xx/EVENT.xx assigned AFTER sort (01=newest). The deck's pre-rendered active card = FIRST slug in src/config/events.json `featured` (`.first` set on it by `resolveEventsPage` in build.js, NOT in the loader). Engine does NOT escape values → raw HTML injection works. `.md-body` scoped CSS in 08-pages.css covers ol (decimal-leading-zero counters), tables, img, hr, inline code, links; `.ev-brief` variant adds typography for the event plate without touching journal pages. Build fails loudly on missing fields or URL-unsafe filenames.
- **Vertical reading pages** (2026-08-24): BOTH article.html AND event.html are vertical — `<body>` has NO `hx-body`, `<main>` NO `data-horizontal`; body:not(.hx-body) rules in 04-layout.css stack sections, horizontal.js falls back to initVertical().
